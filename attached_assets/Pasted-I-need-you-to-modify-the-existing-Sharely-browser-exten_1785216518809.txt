## Existing Sharely functionality

The extension's core purpose is:

1. User logs into Sharely.
2. Sharely retrieves an authorized session-cookie configuration for a subscription/account.
3. Extension receives the cookie data from the Sharely backend.
4. Extension places the supplied cookies into the target website's cookie store using the browser's cookie API where the browser permits this.
5. Extension opens the target website.
6. The user should arrive at the website with the supplied session state, where technically supported.

The existing extension currently uses APIs such as:

* cookies
* storage
* tabs
* contextMenus
* background/service-worker logic
* Sharely backend API

Preserve this functionality and API contract as much as possible.

## SECURITY / AUTHENTICATION

The extension must NEVER ask the user to paste a session cookie manually.

The extension should only receive session data from the authenticated Sharely backend.

Do not log session cookie values to console.
Do not expose session cookie values in the popup UI.
Do not store session cookies in localStorage.
Do not send cookies to third-party servers.
Do not weaken cookie security attributes.

Only use the cookie API to establish session state where the browser explicitly allows it.
