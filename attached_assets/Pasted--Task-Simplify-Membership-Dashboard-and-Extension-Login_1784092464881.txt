# Task — Simplify Membership Dashboard and Extension Login Flow

## Goal

Simplify the entire membership system.

The website dashboard is the main control center for the user.

Users manage:
- Login/logout
- Subscription
- Plan duration
- Purchase
- Upgrade
- Extension download
- Installation tutorial

ONLY from the website dashboard.

The browser extension should NOT have its own login form, access token input, purchase page, or subscription management.

The extension should automatically detect the user's active dashboard login session.

---

## Extension Authentication

The extension must automatically connect to the logged-in website account.

The website dashboard session is the source of truth.

Expected behavior:

1. User logs into the Sharely website.

2. User opens:

/membership/dashboard

3. The extension detects the active website session.

4. The extension calls the Sharely backend to verify the current user.

Example endpoint:

GET /api/membership/extension-session

The request must use the existing authenticated website session.

Backend response example:

{
  "authenticated": true,
  "user": {
    "id": 123,
    "email": "user@example.com"
  },
  "subscription": {
    "active": true,
    "plan": "Pro",
    "expires_at": "2026-08-15T00:00:00Z"
  }
}

5. If the membership is active, the extension automatically becomes logged in.

6. If the user logs out from the website, the extension should detect the invalid session and become logged out.

7. If the user logs into another Sharely account from the website dashboard, the extension should automatically use the new account after session verification.

The extension should periodically verify the session with the backend.

Also verify the session when:

- Extension starts
- Browser starts
- Extension popup opens

DO NOT store raw passwords.

DO NOT expose internal access tokens in the dashboard.

Use the existing secure website authentication/session system.

## Subscription Expiration

When payment is successfully completed:

1. Fetch the purchased plan.

2. Read plan.duration_days.

3. Calculate:

current_period_end = current time + duration_days

Examples:

Starter = +30 days
Pro = +30 days
Team = +60 days

Remove any hardcoded +30 day subscription logic.

The dashboard must use current_period_end to display the expiration date.
